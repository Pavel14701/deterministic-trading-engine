# Conditional P&L diagnostic (опции) — спека frozen ДО кода

## Вопрос

Какая переменная на ВХОДЕ в опционную ногу разделяет winning vs
losing trades по realized P&L? Цель — найти условие, предсказывающее
P&L, а не vol (ловушка «X предсказывает RV → IV движется вместе →
conditional VRP сжимается», трижды подтверждена: 1.1, A3-аналогия,
wave-3 slope).

## Universe (frozen, 2 сегмента учёта)

- **U1 unhedged put legs**: frozen strangle-rolls, put m~0.90,
  все 65 (real prints + proxy entries, флаг mode).
- **U2 unhedged call legs**: то же, call m~1.10, все 65.
- **U3 delta-hedged put legs**: те же 45 legs с prints через
  `_hedge` (band 0.10), как 1.1.

**Объявлено заранее:** U3 n=45 → терцили по 15 < 20 → вердикт U3
по правилу n≥20 априорно «недостаточно данных». U3 считается, но
не может дать ALIVE — это честное следствие выборки.

Роллы помесячные, окна не перекрываются → ноги квази-независимы.

## Переменные на входе (frozen список, 7 + 1 исключена)

1. VRP_entry = DVOL(t_r) − RV30(t_r), pt
2. DVOL percentile (rank по полной выборке DVOL)
3. RV30 percentile (rank по полной выборке RV30)
4. Print-skew = iv_entry − DVOL(t_r), pt (для call-ног — call-skew)
5. Term slope = IV(back 60d) − IV(front 30d) на тот же t_r
   (пары из ts_readout; объявлено: n=22 → вердикт априорно
   «недостаточно данных»)
6. DTE = (nxt − t_r) / 86400000, дней
7. IV_entry level, %
8. Event proximity — **ИСКЛЧЕНА**: событийного календаря в репо
   нет; строить его под этот диаг = новый источник p-hacking.
   Wave 5 — отдельная строка карты со своим пререгом.

Ячейки: 7 переменных × 2 юниверса (U1, U2) × терцили = **14 ячеек**
(+ 7 в U3 со статусом insufficient). Не 80: hold-to-expiry нога
имеет один горизонт, отдельные «горизонты» были бы подгонкой.

## Verdict-правила (frozen)

Ячейка **ALIVE** ⇔ всё сразу:
- n ≥ 20 на терциль;
- медианы PnL терцилей монотонны;
- spread top−bottom терцилей ≥ +0.50% на ногу;
- согласованность: spread одного знака в обеих половинах выборки
  (2021–2023 vs 2024–2026).

Ячейка **TRAP** если: |spearman(X, RV фронт-окна)| ≥ 0.30, а
P&L-разделение слабое (spread < 0.50%) — «vol-proxy», не сигнал.

Иначе — **NULL** (не разделяет).

Итог диагностике: ≥1 ALIVE → conditional prereg только по этой
переменной (и это НЕ рестарт закрытых стратегий, а новая строка
карты). Все NULL/TRAP → **опционный трек закрыт как класс** с
формулировкой «не источник alpha в доступных формах».

## Запреты

- Не перебирать комбинации переменных до «работающей».
- Не строить вывод на ячейке с n < 20 («недостаточно данных»,
  не «нет сигнала»).
- Не путать «предсказывает RV» с «предсказывает P&L».
- Один ран: `runs/cond_pnl_diag.log`; падение = restart с записью.
